MLA

Multi-Head Latent Attention (MLA), introduced by DeepSeek, solves a core bottleneck in Transformer inference: the massive size and memory bandwidth cost of the KV Cache.

Chris McCormick

While Grouped-Query Attention (GQA) reduces KV heads at the cost of model expressiveness, MLA achieves extreme compression without losing representational capacity by using low-rank latent projections and algebraic weight absorption.

Chris McCormick

1. Why Standard Multi-Head Attention (MHA) Is Costly

For an input token vector xt∈Rd\mathbf{x}_t \in \mathbb{R}^dxt​∈Rd across nhn_hnh​ heads, each head generates query, key, and value vectors of dimension dhd_hdh​:

qt,i=xtWiQ,kt,i=xtWiK,vt,i=xtWiV(i=1,…,nh) \mathbf{q}_{t,i} = \mathbf{x}_t \mathbf{W}_i^Q, \quad \mathbf{k}_{t,i} = \mathbf{x}_t \mathbf{W}_i^K, \quad \mathbf{v}_{t,i} = \mathbf{x}_t \mathbf{W}_i^V \quad (i = 1, \dots, n_h) qt,i​=xt​WiQ​,kt,i​=xt​WiK​,vt,i​=xt​WiV​(i=1,…,nh​)

During autoregressive generation, we must store all past keys and values in memory:

KV Cache per token=2×nh×dh numbers \text{KV Cache per token} = 2 \times n_h \times d_h \text{ numbers} KV Cache per token=2×nh​×dh​ numbers

For large models (e.g., 128 heads, head dimension 128), that is over 32,000 floats per token, dominating memory footprint and memory-bus bandwidth.

Chris McCormick

2. Multi-Head Latent Attention: Without RoPE

The central intuition of MLA is simple: instead of storing full multi-head keys and values, compress each token’s key and value representations into a single low-dimensional latent vector.

The Compression (Down-Projection)

Instead of projecting xt\mathbf{x}_txt​ directly to nhn_hnh​ heads, we down-project it into a compact latent vector ctKV∈Rdc\mathbf{c}_t^{KV} \in \mathbb{R}^{d_c}ctKV​∈Rdc​ where dc≪nh×dhd_c \ll n_h \times d_hdc​≪nh​×dh​:

ctKV=xtWDKV \mathbf{c}_t^{KV} = \mathbf{x}_t \mathbf{W}^{DKV} ctKV​=xt​WDKV
  • WDKV∈Rd×dc\mathbf{W}^{DKV} \in \mathbb{R}^{d \times d_c}WDKV∈Rd×dc​ is the down-projection matrix.
  • In the KV cache, we only store ctKV\mathbf{c}_t^{KV}ctKV​ (a single vector of size dcd_cdc​ per token, rather than 2⋅nh⋅dh2 \cdot n_h \cdot d_h2⋅nh​⋅dh​). Chris McCormick

(Queries are also compressed during training to save activation memory via ctQ=xtWDQ\mathbf{c}_t^Q = \mathbf{x}_t \mathbf{W}^{DQ}ctQ​=xt​WDQ, then up-projected to qt,i=ctQWiUQ\mathbf{q}_{t,i} = \mathbf{c}_t^Q \mathbf{W}_i^{UQ}qt,i​=ctQ​WiUQ​, though query compression does not affect KV cache sizing.)

Generation & The “Weight Absorption” Trick

To compute attention, keys and values for head iii are theoretically uncompressed using up-projection matrices:

kj,i=cjKVWiUK,vj,i=cjKVWiUV \mathbf{k}_{j,i} = \mathbf{c}_j^{KV} \mathbf{W}_i^{UK}, \quad \mathbf{v}_{j,i} = \mathbf{c}_j^{KV} \mathbf{W}_i^{UV} kj,i​=cjKV​WiUK​,vj,i​=cjKV​WiUV​

where WiUK∈Rdc×dh\mathbf{W}_i^{UK} \in \mathbb{R}^{d_c \times d_h}WiUK​∈Rdc​×dh​ and WiUV∈Rdc×dh\mathbf{W}_i^{UV} \in \mathbb{R}^{d_c \times d_h}WiUV​∈Rdc​×dh​.

The attention score between query token ttt and key token jjj for head iii is:

Scorei(t,j)=qt,ikj,iT=qt,i(cjKVWiUK)T=qt,i(WiUK)T(cjKV)T \text{Score}_{i}(t, j) = \mathbf{q}_{t,i} \mathbf{k}_{j,i}^T = \mathbf{q}_{t,i} \left( \mathbf{c}_j^{KV} \mathbf{W}_i^{UK} \right)^T = \mathbf{q}_{t,i} (\mathbf{W}_i^{UK})^T (\mathbf{c}_j^{KV})^T Scorei​(t,j)=qt,i​kj,iT​=qt,i​(cjKV​WiUK​)T=qt,i​(WiUK​)T(cjKV​)T

Because matrix multiplication is associative, we can group the terms differently:

Scorei(t,j)=(qt,i(WiUK)T)⏟qt,i′∈Rdc(cjKV)T \text{Score}_{i}(t, j) = \underbrace{\left(\mathbf{q}_{t,i} (\mathbf{W}_i^{UK})^T\right)}_{\mathbf{q}'_{t,i} \in \mathbb{R}^{d_c}} (\mathbf{c}_j^{KV})^T Scorei​(t,j)=qt,i′​∈Rdc​(qt,i​(WiUK​)T)​​(cjKV​)T

This provides a major performance optimization:

  1. Never decompress keys in memory: We project the single active query vector down into the latent space: qt,i′=qt,i(WiUK)T∈Rdc\mathbf{q}'_{t,i} = \mathbf{q}_{t,i} (\mathbf{W}_i^{UK})^T \in \mathbb{R}^{d_c}qt,i′​=qt,i​(WiUK​)T∈Rdc​.
  2. Compute the dot-product directly against the cached latent cjKV\mathbf{c}_j^{KV}cjKV​.
  3. For values, WiUV\mathbf{W}_i^{UV}WiUV​ can similarly be absorbed directly into the output projection WO\mathbf{W}^OWO.

3. The RoPE Problem

Rotary Position Embedding (RoPE) injects relative token distance by rotating vectors with a position-dependent orthogonal matrix Rt\mathbf{R}_tRt​:

Outcome School

qt→qtRt,kj→kjRj \mathbf{q}_{t} \to \mathbf{q}_t \mathbf{R}_t, \quad \mathbf{k}_{j} \to \mathbf{k}_j \mathbf{R}_j qt​→qt​Rt​,kj​→kj​Rj​

If we apply standard RoPE to the decompressed key kj,i=cjKVWiUK\mathbf{k}_{j,i} = \mathbf{c}_j^{KV} \mathbf{W}_i^{UK}kj,i​=cjKV​WiUK​:

kj,iRoPE=cjKVWiUKRj \mathbf{k}_{j,i}^{\text{RoPE}} = \mathbf{c}_j^{KV} \mathbf{W}_i^{UK} \mathbf{R}_j kj,iRoPE​=cjKV​WiUK​Rj​

The attention dot-product becomes:

Scorei(t,j)=(qt,iRt)(kj,iRoPE)T=qt,iRtRjT(WiUK)T(cjKV)T \text{Score}_{i}(t, j) = (\mathbf{q}_{t,i} \mathbf{R}_t) (\mathbf{k}_{j,i}^{\text{RoPE}})^T = \mathbf{q}_{t,i} \mathbf{R}_t \mathbf{R}_j^T (\mathbf{W}_i^{UK})^T (\mathbf{c}_j^{KV})^T Scorei​(t,j)=(qt,i​Rt​)(kj,iRoPE​)T=qt,i​Rt​RjT​(WiUK​)T(cjKV​)T

Because RjT\mathbf{R}_j^TRjT​ sits squarely between WiUK\mathbf{W}_i^{UK}WiUK​ and cjKV\mathbf{c}_j^{KV}cjKV​, weight absorption breaks. You would either have to:

  • Decompress and rotate keys for every token in history at runtime (compute-prohibitive), or varmology
  • Cache the uncompressed, rotated keys across all heads (defeating the purpose of compressing the KV cache). varmology

4. Multi-Head Latent Attention: With Decoupled RoPE

MLA resolves this conflict by separating attention into two distinct parallel streams: a content stream and a position stream.

The Positional Pathway

  1. Decoupled Key: We project token xt\mathbf{x}_txt​ directly to a shared, low-dimensional position vector ktR∈RdR\mathbf{k}_t^R \in \mathbb{R}^{d_R}ktR​∈RdR​ (typically dR=64d_R = 64dR​=64), and apply rotation Rt\mathbf{R}_tRt​ to it: ktR=RoPE(xtWKR) \mathbf{k}_{t}^R = \text{RoPE}\left(\mathbf{x}_t \mathbf{W}^{KR}\right) ktR​=RoPE(xt​WKR) (Notice that all heads share this positional key or use a unified projection.) arXiv
  2. Decoupled Query: We project queries into both a content query qt,iC∈Rdh\mathbf{q}_{t,i}^C \in \mathbb{R}^{d_h}qt,iC​∈Rdh​ and a positional query qt,iR∈RdR\mathbf{q}_{t,i}^R \in \mathbb{R}^{d_R}qt,iR​∈RdR​: qt,iR=RoPE(ctQWiQR) \mathbf{q}_{t,i}^R = \text{RoPE}\left(\mathbf{c}_t^Q \mathbf{W}_i^{QR}\right) qt,iR​=RoPE(ctQ​WiQR​)

The Attention Score Calculation

The final query and key vectors are formed by concatenating their content and positional components:

qt,i=[qt,iC  ;  qt,iR],kj,i=[kj,iC  ;  kjR] \mathbf{q}_{t,i} = \left[ \mathbf{q}_{t,i}^C \;;\; \mathbf{q}_{t,i}^R \right], \quad \mathbf{k}_{j,i} = \left[ \mathbf{k}_{j,i}^C \;;\; \mathbf{k}_j^R \right] qt,i​=[qt,iC​;qt,iR​],kj,i​=[kj,iC​;kjR​]

The dot-product naturally splits into two additive terms:

Scorei(t,j)=qt,iC(kj,iC)T+qt,iR(kjR)T \text{Score}_{i}(t, j) = \mathbf{q}_{t,i}^C (\mathbf{k}_{j,i}^C)^T + \mathbf{q}_{t,i}^R (\mathbf{k}_j^R)^T Scorei​(t,j)=qt,iC​(kj,iC​)T+qt,iR​(kjR​)T

Substitute the content and RoPE representations:

Scorei(t,j)=(qt,iC(WiUK)T)⏟Absorbed: Rdc(cjKV)T+qt,iR(kjR)T⏟RoPE dot-product: RdR \text{Score}_{i}(t, j) = \underbrace{\left(\mathbf{q}_{t,i}^C (\mathbf{W}_i^{UK})^T\right)}_{\text{Absorbed: } \mathbb{R}^{d_c}} (\mathbf{c}_j^{KV})^T + \underbrace{\mathbf{q}_{t,i}^R (\mathbf{k}_j^R)^T}_{\text{RoPE dot-product: } \mathbb{R}^{d_R}} Scorei​(t,j)=Absorbed: Rdc​(qt,iC​(WiUK​)T)​​(cjKV​)T+RoPE dot-product: RdR​qt,iR​(kjR​)T​​
  • The content component retains full weight absorption—keys do not need to be uncompressed.
  • The position component is small (dR≈64d_R \approx 64dR​≈64) and decoupled from head-expansion. Chris McCormick
