Context parallelism

Context Parallelism (CP)—often referred to as Sequence Parallelism across nodes, or realized via primitives like RingAttention and DeepSpeed-Ulysses—is an intra-layer distributed training and inference paradigm that partitions the sequence (context) dimension SSS across PPP accelerators while leaving the model’s weight matrices intact on each rank.

Where Tensor Parallelism (TP) splits the hidden dimension hhh (or attention heads hheadsh_{\text{heads}}hheads​) and hits an intra-node barrier (P≤8P \le 8P≤8), Context Parallelism enables scaling sequence lengths to hundreds of thousands or millions of tokens (S≥1MS \ge 1\text{M}S≥1M) across multi-node clusters by distributing activation memory and compute quadratically tied to sequence length.

1. The Scaling Bottleneck CP Resolves

In standard Transformer architectures, self-attention memory and compute scale with sequence length SSS:

  • Compute (FLOPs): O(S2⋅d)\mathcal{O}(S^2 \cdot d)O(S2⋅d) per head.
  • Activation Memory: Attention logits require O(B⋅h⋅S2)\mathcal{O}(B \cdot h \cdot S^2)O(B⋅h⋅S2) in vanilla attention, or O(B⋅h⋅S⋅d)\mathcal{O}(B \cdot h \cdot S \cdot d)O(B⋅h⋅S⋅d) under online Softmax engines like FlashAttention.
  • KV Cache (Inference): Scales linearly with SSS per request: 2×2×B×S×L×hKV×dk2 \times 2 \times B \times S \times L \times h_{KV} \times d_k2×2×B×S×L×hKV​×dk​ bytes.

When scaling S→128kS \to 128\text{k}S→128k or 1M1\text{M}1M, a single GPU’s High-Bandwidth Memory (HBM) is overwhelmed by activations even if the model weights fit completely. TP cannot shard SSS inside the core attention computation without cross-head communication, and Pipeline Parallelism (PP) requires activations of the entire sequence to be buffered between stage handoffs. Context Parallelism directly addresses this by slicing inputs:

X∈RB×S×d  ⟹  X(p)∈RB×SP×d,p∈{0,1,…,P−1} X \in \mathbb{R}^{B \times S \times d} \implies X^{(p)} \in \mathbb{R}^{B \times \frac{S}{P} \times d}, \quad p \in \{0, 1, \dots, P-1\} X∈RB×S×d⟹X(p)∈RB×PS​×d,p∈{0,1,…,P−1}

Each rank holds a sub-sequence of length s=S/Ps = S/Ps=S/P.

2. The Core Challenge: Cross-Rank Attention

Feedforward networks (MLPs), RMSNorm/LayerNorm, and embedding lookups operate element-wise or across token features independently. Sharding along SSS means these layers run locally on rank ppp with zero cross-rank communication:

HMLP(p)=MLP(X(p)) H_{\text{MLP}}^{(p)} = \text{MLP}\left(X^{(p)}\right) HMLP(p)​=MLP(X(p))

The fundamental challenge arises strictly at Self-Attention: token iii on rank ppp must attend to all tokens j≤ij \le ij≤i (under causal masking) or all tokens j∈[0,S−1]j \in [0, S-1]j∈[0,S−1] (under bidirectional attention), many of which reside in the memory of ranks q≠pq \ne pq=p.

Two primary architectures have emerged to solve this: RingAttention and DeepSpeed-Ulysses.

3. Paradigm A: RingAttention (P2P Overlapped Rings)

Proposed by Hao Liu et al., RingAttention distributes the query, key, and value sequences across a logical ring of PPP GPUs.

Sharding

Each GPU ppp permanently holds its local chunk of Queries, Keys, and Values:

Q(p),K(p),V(p)∈RB×SP×h×dk Q^{(p)}, K^{(p)}, V^{(p)} \in \mathbb{R}^{B \times \frac{S}{P} \times h \times d_k} Q(p),K(p),V(p)∈RB×PS​×h×dk​

Execution Loop

Instead of collecting all Keys and Values globally via an All-Gather (which would trigger an out-of-memory exception), RingAttention streams KKK and VVV in a bucket-brigade ring across PPP steps:

Step 0: GPU p computes Attention(Q^(p), K^(p), V^(p))
  │
  ├── P2P Send K^(p), V^(p) to GPU (p + 1)
  └── P2P Recv K^(p-1), V^(p-1) from GPU (p - 1)
  │
Step 1: GPU p computes Attention(Q^(p), K^(p-1), V^(p-1)) [Overlapped with step 2 transfer]
  │
  └── ... repeat for P - 1 shifts ...
┌───────────────────────────────┐
       ▼                               │
   [GPU 0] ──► (K, V) ──► [GPU 1] ──► [GPU 2] ──► [GPU 3] ──┐
      ▲                                                      │
      └──────────────────────────────────────────────────────┘

For each block step k∈[0,P−1]k \in [0, P-1]k∈[0,P−1], rank ppp maintains running statistics:

  • Local maximum logit: mi(k)∈Rm_i^{(k)} \in \mathbb{R}mi(k)​∈R

Compute-Communication Overlap

RingAttention completely hides network latency if the time to compute local attention on a block of size SP\frac{S}{P}PS​ exceeds the point-to-point (P2P) transfer time of (K,V)(K, V)(K,V) over interconnect links:

Tcompute=4⋅B⋅(S/P)2⋅h⋅dkFLOPsGPU≥Tcomm=2⋅B⋅(S/P)⋅hKV⋅dk×sizeof(FP16)Bandwidthlink T_{\text{compute}} = \frac{4 \cdot B \cdot (S/P)^2 \cdot h \cdot d_k}{\text{FLOPs}_{\text{GPU}}} \quad \ge \quad T_{\text{comm}} = \frac{2 \cdot B \cdot (S/P) \cdot h_{KV} \cdot d_k \times \text{sizeof(FP16)}}{\text{Bandwidth}_{\text{link}}} Tcompute​=FLOPsGPU​4⋅B⋅(S/P)2⋅h⋅dk​​≥Tcomm​=Bandwidthlink​2⋅B⋅(S/P)⋅hKV​⋅dk​×sizeof(FP16)​

As long as the per-GPU token chunk SP\frac{S}{P}PS​ is large enough (typically ≥2k−4k\ge 2\text{k} - 4\text{k}≥2k−4k tokens), communication is 100% hidden behind compute.

4. Causal Masking Imbalance and Striped RingAttention

In causal auto-regressive models, token iii can only attend to token jjj where j≤ij \le ij≤i.

If sequences are sliced contiguously into linear chunks:

  • GPU 0 gets tokens [0,SP−1][0, \frac{S}{P}-1][0,PS​−1]: It only computes self-attention on its own tokens; all subsequent ring chunks from GPUs 1…P−11 \dots P-11…P−1 are masked out (0%0\%0% compute on those steps).
  • GPU P−1P-1P−1 gets tokens [(P−1)SP,S−1][\frac{(P-1)S}{P}, S-1][P(P−1)S​,S−1]: It must attend to all past tokens (100%100\%100% compute across all PPP steps).

This creates an extreme compute imbalance where GPU 0 sits idle while GPU P−1P-1P−1 bottlenecks the cluster, yielding ~50% hardware underutilization.

Naive Block Assignment:
GPU 0: [■ □ □ □]  -> 25% compute
GPU 1: [■ ■ □ □]  -> 50% compute
GPU 2: [■ ■ ■ □]  -> 75% compute
GPU 3: [■ ■ ■ ■]  -> 100% compute (Bottleneck)

Striped Partitioning (Round-Robin Slicing)

To restore perfect load balance, Striped Attention maps tokens to GPUs using an interleaved round-robin stride:

Token t  ⟹  GPU (t mod P) \text{Token } t \implies \text{GPU } (t \bmod P) Token t⟹GPU (tmodP)

Each GPU holds an evenly distributed mixture of early, middle, and late tokens. The number of active causal attention pairs is virtually identical across all PPP ranks throughout the ring rotations, returning hardware compute efficiency to near 100%100\%100%.

5. Paradigm B: DeepSpeed-Ulysses (All-to-All Transposition)

While RingAttention uses circular asynchronous P2P, DeepSpeed-Ulysses leverages global All-to-All collective communication primitives to swap between sequence partitioning and attention-head partitioning.

Input: Slices along Sequence [S/P, H]
               │
               ▼
   [ All-to-All-v Collective ]  <-- Transposes (S/P, H) -> (S, H/P)
               │
               ▼
Compute Attention locally on [S, H/P] via FlashAttention (Full Sequence, Subset of Heads)
               │
               ▼
   [ All-to-All-v Collective ]  <-- Transposes (S, H/P) -> (S/P, H)
               │
               ▼
Output: Slices along Sequence [S/P, H]
  1. Before Attention: Activations are partitioned along sequence length SP\frac{S}{P}PS​, holding all heads HHH.
  2. First All-to-All: Ranks exchange slices so each GPU now holds the entire sequence length SSS, but only a subset of heads HP\frac{H}{P}PH​.
  3. Local Compute: Standard optimized FlashAttention runs locally on full context SSS for HP\frac{H}{P}PH​ heads with zero custom communication or online softmax stitching.
  4. Second All-to-All: The attention output tensor is transposed back from [S,HP][S, \frac{H}{P}][S,PH​] to [SP,H][\frac{S}{P}, H][PS​,H] to resume element-wise MLP computation.

6. Integration in 4D Parallelism (TP + PP + DP/FSDP + CP)

In large-scale production training (e.g., Llama 3, DeepSeek-V3), Context Parallelism forms a dedicated dimension in the parallel process grid:

World Size=TP×PP×DP (FSDP)×CP \text{World Size} = \text{TP} \times \text{PP} \times \text{DP (FSDP)} \times \text{CP} World Size=TP×PP×DP (FSDP)×CP
  • Intra-node: Tensor Parallelism (TP ≤8\le 8≤8) operates within a single NVLink domain due to sub-microsecond latency demands.
  • Low-tier Inter-node: Context Parallelism (CP) operates across nearby nodes, hiding inter-node network latency behind the compute of large sequence chunks.
  • Global Grid: ZeRO-3 / FSDP shards optimizer states across the data-parallel group, while Pipeline Parallelism (PP) connects distant clusters or stages across minimal communication boundaries.

During backpropagation, CP requires reversing the communication ring or re-executing All-to-All to distribute activation gradients ∇Q,∇K,∇V\nabla_Q, \nabla_K, \nabla_V∇Q​,∇K​,∇V​, maintaining an identical memory footprint reduction throughout the backward pass.
