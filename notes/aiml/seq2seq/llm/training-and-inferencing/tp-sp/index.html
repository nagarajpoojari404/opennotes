TP + SP

TP + SP

Tensor Parallelism (TP) is an intra-layer model-parallelism technique that splits individual weight matrices, matrix multiplications (GEMMs), and activations across multiple accelerators (GPUs/TPUs).

Unlike Pipeline Parallelism (PP)—which partitions models across sequential layers and introduces execution bubbles—or Data Parallelism (DP/FSDP)—which replicates model weights or shards parameters across batch dimensions—Tensor Parallelism splits individual weight tensors within a layer to compute a single layer cooperatively across multiple ranks.

1. Mathematical Foundations: 1D Matrix Partitioning

Consider a standard fully connected layer computing Y=Activation(XW)Y = \text{Activation}(XW)Y=Activation(XW), where:

  • Input activation X∈RB×dinX \in \mathbb{R}^{B \times d_{in}}X∈RB×din​ (batch size B×B \timesB× sequence length SSS, flattened to dimension BBB)
  • Weight matrix W∈Rdin×doutW \in \mathbb{R}^{d_{in} \times d_{out}}W∈Rdin​×dout​
  • Output activation Y∈RB×doutY \in \mathbb{R}^{B \times d_{out}}Y∈RB×dout​

Across NNN parallel processing ranks, a matrix multiplication can be sliced along its columns or its rows.

Column-Parallel Linear Layer

The weight matrix WWW is sliced along its column dimension into NNN equal chunks:

W=[W1W2…WN],Wi∈Rdin×doutN W = \begin{bmatrix} W_1 & W_2 & \dots & W_N \end{bmatrix}, \quad W_i \in \mathbb{R}^{d_{in} \times \frac{d_{out}}{N}} W=[W1​​W2​​…​WN​​],Wi​∈Rdin​×Ndout​​

Each GPU iii holds the full input XXX and its local shard WiW_iWi​:

Yi=XWi∈RB×doutN Y_i = X W_i \in \mathbb{R}^{B \times \frac{d_{out}}{N}} Yi​=XWi​∈RB×Ndout​​

Because linear matrix multiplication is distributive across columns:

Y=[Y1Y2…YN] Y = \begin{bmatrix} Y_1 & Y_2 & \dots & Y_N \end{bmatrix} Y=[Y1​​Y2​​…​YN​​]

If an element-wise non-linearity σ\sigmaσ (e.g., GeLU, SwiGLU) is applied, it commutes with column concatenation:

σ(Y)=[σ(Y1)σ(Y2)…σ(YN)] \sigma(Y) = \begin{bmatrix} \sigma(Y_1) & \sigma(Y_2) & \dots & \sigma(Y_N) \end{bmatrix} σ(Y)=[σ(Y1​)​σ(Y2​)​…​σ(YN​)​]
  • Forward pass: Each rank computes YiY_iYi​ locally with zero communication.
  • Communication required: None yet, as long as the subsequent operation can consume column-sharded tensors.

Row-Parallel Linear Layer

The weight matrix WWW is sliced along its row (contracting) dimension:

W=[W1W2⋮WN],Wi∈RdinN×dout W = \begin{bmatrix} W_1 \\ W_2 \\ \vdots \\ W_N \end{bmatrix}, \quad W_i \in \mathbb{R}^{\frac{d_{in}}{N} \times d_{out}} W=​W1​W2​⋮WN​​​,Wi​∈RNdin​​×dout​

To match dimensions, the input XXX must be partitioned along its column dimension: X=[X1,X2,…,XN]X = [X_1, X_2, \dots, X_N]X=[X1​,X2​,…,XN​], where Xi∈RB×dinNX_i \in \mathbb{R}^{B \times \frac{d_{in}}{N}}Xi​∈RB×Ndin​​.

Each rank computes a local partial product:

Zi=XiWi∈RB×dout Z_i = X_i W_i \in \mathbb{R}^{B \times d_{out}} Zi​=Xi​Wi​∈RB×dout​

The full mathematical output YYY is the summation of these partial products:

Y=∑i=1NZi=∑i=1NXiWi=XW Y = \sum_{i=1}^N Z_i = \sum_{i=1}^N X_i W_i = XW Y=i=1∑N​Zi​=i=1∑N​Xi​Wi​=XW
  • Forward pass: Requires an All-Reduce (sum) collective across all NNN ranks to aggregate ZiZ_iZi​ into YYY.

2. The Megatron-LM Coupling Principle

Naively chaining parallel layers requires an All-Gather after each column-parallel layer and an All-Reduce after each row-parallel layer, creating substantial collective communication overhead.

The core insight of Megatron-LM is pairing Column-Parallel and Row-Parallel layers back-to-back to cancel intermediate communications.

MLP Forward Pass:
X (Replicated) 
  │
  ├──► GPU 0: [W1_col] ──► GeLU ──► [W2_row] ──┐
  │                                            │ (All-Reduce Sum)
  └──► GPU 1: [W2_col] ──► GeLU ──► [W2_row] ──┴──► Output (Replicated)

A. Multi-Layer Perceptron (MLP / FFN) Block

A standard Transformer MLP consists of two projections: Z=σ(XWgate)⊙(XWup)Z = \sigma(X W_{gate}) \odot (X W_{up})Z=σ(XWgate​)⊙(XWup​) followed by an output projection WdownW_{down}Wdown​.

  1. First Layer (Column-Parallel):
    • W1∈Rh×4hW_1 \in \mathbb{R}^{h \times 4h}W1​∈Rh×4h is sliced column-wise into [W1,1,…,W1,N][W_{1,1}, \dots, W_{1,N}][W1,1​,…,W1,N​], each of size h×4hNh \times \frac{4h}{N}h×N4h​.
      • Each rank computes Hi=σ(XW1,i)H_i = \sigma(X W_{1,i})Hi​=σ(XW1,i​).
      • Communication: 0 bytes.
  2. Second Layer (Row-Parallel):
    • W2∈R4h×hW_2 \in \mathbb{R}^{4h \times h}W2​∈R4h×h is sliced row-wise into [W2,1;… ;W2,N][W_{2,1}; \dots; W_{2,N}][W2,1​;…;W2,N​], each of size 4hN×h\frac{4h}{N} \times hN4h​×h.
      • Each rank multiplies its local intermediate activation HiH_iHi​ with W2,iW_{2,i}W2,i​: Y~i=HiW2,i \widetilde{Y}_i = H_i W_{2,i} Yi​=Hi​W2,i​
      • An All-Reduce sum collective is executed across the NNN ranks: Y=∑i=1NY~i Y = \sum_{i=1}^N \widetilde{Y}_i Y=i=1∑N​Yi​
      • Communication: Exactly 1 All-Reduce per MLP block.

B. Multi-Head Attention (MHA) Block

Attention naturally parallelizes across attention heads (hhh heads, each with head dimension dkd_kdk​):

  1. Q,K,VQ, K, VQ,K,V Projections (Column-Parallel):
    • The projection weights WQ,WK,WV∈Rh×hW_Q, W_K, W_V \in \mathbb{R}^{h \times h}WQ​,WK​,WV​∈Rh×h are sliced along columns such that each GPU receives hheadsN\frac{h_{\text{heads}}}{N}Nhheads​​ complete heads.
      • No communication is required to split attention heads; each rank gets its local Qi,Ki,ViQ_i, K_i, V_iQi​,Ki​,Vi​.
  2. Local Attention Computation:
    • Each rank performs scaled dot-product attention independently on its local head partition: Attentioni=Softmax(QiKiTdk)Vi \text{Attention}_i = \text{Softmax}\left(\frac{Q_i K_i^T}{\sqrt{d_k}}\right) V_i Attentioni​=Softmax(dk​​Qi​KiT​​)Vi​
      • Communication: 0 bytes.
  3. Output Projection (Row-Parallel):
    • The output projection matrix WO∈Rh×hW_O \in \mathbb{R}^{h \times h}WO​∈Rh×h is sliced row-wise: [WO,1;… ;WO,N][W_{O,1}; \dots; W_{O,N}][WO,1​;…;WO,N​].
      • Each rank computes O~i=Attentioni⋅WO,i\widetilde{O}_i = \text{Attention}_i \cdot W_{O,i}Oi​=Attentioni​⋅WO,i​.
      • An All-Reduce is executed to produce the unified context tensor: O=∑i=1NO~i O = \sum_{i=1}^N \widetilde{O}_i O=i=1∑N​Oi​
      • Communication: Exactly 1 All-Reduce per Attention block.

3. Forward vs. Backward Conjugate Collectives

Under reverse-mode automatic differentiation, the backward pass of a linear transformation swaps the transpose of the forward communication primitive:

Layer TypeForward CommunicationBackward Communication (Gradient ∇X\nabla X∇X)Backward Parameter Gradient (∇W\nabla W∇W)
Column ParallelNone (Identity / Broadcast input)All-Reduce (∇X=∑i∇YiWi⊤\nabla X=\sum_i\nabla Y_iW_i^\top∇X=∑i​∇Yi​Wi⊤​)Local: X⊤∇YiX^\top\nabla Y_iX⊤∇Yi​
Row ParallelAll-Reduce (Y=∑iXiWiY=\sum_i X_iW_iY=∑i​Xi​Wi​)None (Identity / Sliced ∇Y\nabla Y∇Y)Local: Xi⊤∇YX_i^\top\nabla YXi⊤​∇Y

Each Transformer layer requires:

  • Forward Pass: 2 All-Reduces (1 for Attention output, 1 for MLP output).
  • Backward Pass: 2 All-Reduces (1 across the input of Row-Parallel Attention, 1 across the input of Row-Parallel MLP).

4. Communication Overhead and Topology Constraints

A standard Ring All-Reduce transfers 2⋅N−1N⋅S2 \cdot \frac{N-1}{N} \cdot S2⋅NN−1​⋅S bytes for a tensor of size SSS.

For a Transformer layer with sequence length LLL, batch size BBB, and hidden dimension hhh:

  • The tensor transmitted in each All-Reduce is activation Y∈RB×L×hY \in \mathbb{R}^{B \times L \times h}Y∈RB×L×h.
  • In 16-bit precision (FP16/BF16), total bytes per All-Reduce: Bytes=2×B×L×h×2=4BLh \text{Bytes} = 2 \times B \times L \times h \times 2 = 4BLh Bytes=2×B×L×h×2=4BLh
  • Total forward communication per layer: VolumeFWD=2×2(N−1N)(2BLh)=8BLh(N−1N) bytes \text{Volume}_{\text{FWD}} = 2 \times 2 \left(\frac{N-1}{N}\right) (2BLh) = 8BLh \left(\frac{N-1}{N}\right) \text{ bytes} VolumeFWD​=2×2(NN−1​)(2BLh)=8BLh(NN−1​) bytes

Because this communication happens on every single Transformer layer in the critical path (blocking further GEMM computation), Tensor Parallelism has strict latency requirements:

  • Bandwidth bottleneck: Inter-node networking (e.g., 400 Gbps / 50 GB/s HDR/NDR InfiniBand) introduces high latency stalls relative to kernel execution times.
  • Hardware constraint: Tensor Parallelism is almost exclusively restricted to intra-node domains linked via high-speed interconnects (NVLink / NVSwitch at 900 GB/s to 1.8 TB/s per GPU). TP degree is typically set to N≤8N \le 8N≤8 (matching single-node GPU density).

5. Evolution: Sequence Parallelism (Megatron-SP)

In vanilla 1D TP, the operations outside the Attention and MLP blocks—specifically LayerNorm and Dropout—are replicated identically across all NNN ranks:

Vanilla TP:
Input ──► [LayerNorm (Replicated)] ──► [Col-GEMM] ──► ... ──► [Row-GEMM] ──► [All-Reduce] ──► [Dropout]

This causes two problems:

  1. Redundant compute for LayerNorm/Dropout.
  2. Activation memory for LayerNorm inputs/outputs cannot be sharded, dominating memory consumption at long contexts (L≥8kL \ge 8\text{k}L≥8k).

Sequence Parallelism (SP) solves this by observing that the All-Reduce operation in Row-Parallel linear layers is decomposed into:

All-Reduce=Reduce-Scatter+All-Gather \text{All-Reduce} = \text{Reduce-Scatter} + \text{All-Gather} All-Reduce=Reduce-Scatter+All-Gather

Instead of running an All-Reduce at the end of the row-parallel projection, Megatron-SP runs a Reduce-Scatter:

  1. The partial sums are reduced and simultaneously scattered along the sequence dimension (L/NL/NL/N).
  2. LayerNorm and Dropout execute on local slices of sequence length LN\frac{L}{N}NL​ with zero communication.
  3. Before the next Column-Parallel projection, an All-Gather reassembles the full sequence across all ranks.
Megatron-SP:
[Row-GEMM] ──► [Reduce-Scatter along S] ──► [LayerNorm on S/N] ──► [Dropout on S/N] ──► [All-Gather along S] ──► [Col-GEMM]

Communication volume remains identical to vanilla 1D TP (since Cost(Reduce-Scatter)+Cost(All-Gather)=Cost(All-Reduce)\text{Cost}(\text{Reduce-Scatter}) + \text{Cost}(\text{All-Gather}) = \text{Cost}(\text{All-Reduce})Cost(Reduce-Scatter)+Cost(All-Gather)=Cost(All-Reduce)), but activation memory from LayerNorm and Dropout drops by a factor of NNN.
